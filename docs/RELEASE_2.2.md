## 3. 修了什么

### 3.1 缺陷（7 个）

| # | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 全空时显示「缺 20 项」，实际只有 12 个输入项 | 缺项计数把同一输入项在下游公式里重复累加 | 只统计未填的底层输入项 |
| 2 | 提示直接吐内部 id：「缺：mainTax」 | 缺项用节点 id 输出，没做中文名映射 | `labelOfNode` + 落到可填的底层输入项 |
| 3 | 未填金额时分录却显示「已配平」（借贷都是 0.00） | 全空时差额确实为 0，被判 balanced | 新增四态 `empty / pending / balanced / error` |
| 4 | 「收到货款」两个规则同分，谁标题靠前谁当选 | 关键词跨规则重叠；并列无提示 | 关键词归位 + `isAmbiguous` 并列提示 |
| 5 | 备查式分录默认全选，一填金额就报"多选一" | 漏标互斥组；默认 picks = 全部行 | 补互斥组 + `recommendedPicks` + 组内切换 |
| 6 | 盘点差异出现 `0.30000000000000004` | 直接 `String(a - b)` | 舍入到分再转字符串 |
| 7 | CSV 导出可被公式注入，`\r` 未转义 | 转义只判 `" , \n` | 统一到 `csv-export.js` 并同步修 `tools.js` |
| 8 | **懒加载页面加载失败时一直转圈、随后空白，用户没有任何出路** | `defineAsyncComponent` 的 `loadingComponent` 永远拿不到 `error`（Vue 只给 `errorComponent` 传），所以 `ViewLoading` 里那段"加载失败"UI 是**死代码**；不提供 `errorComponent` 时 `fail()` 之后什么都不渲染 | 改为自管状态的 `lazyView`：自动重试 2 次 + 一个**确定有效**的出口（带时间戳的文档级重载，普通 reload 甩不掉"子资源已被记为失败"的缓存）+ 保活页面切回自动重试 |

### 3.2 验证工具本身的三个缺陷（此前长期误报）

- 懒加载探针把同一视图的 `.css` 当成"第二次 chunk 请求" → 断言恒假。
- 路由探针在 iframe `load` 之前操作 → hash 变更与初始导航合并成一条记录，`back()` 无处可回。
  另修掉一条恒真断言（`typeof x !== 'undefined' || true`）。

**这三条此前一直记为"浏览器断言拿不到干净结果"。结论是：不是应用缺陷，是断言写错了。**

### 3.3 断言强度（第 8 个缺陷为什么差点漏掉）

原来底稿页的断言是 `document.body.innerText.includes('底稿')`，
而**导航栏里就有「底稿文书」**，这条断言恒真，页面是白的也照样通过。
五个懒加载页面里有四个都是这种写法，已全部改成
「等页面内容出现 **且** 占位符不存在」。

**规则**：断言"看得见某段文字"时，必须先确认这段文字**只可能来自被断言的那个视图**。
拿导航标签 / 面包屑 / 页面标题当判据，等于在断言应用外壳，不是在断言页面。

## 4. 已知限制（不修，但要说明）

| 项 | 说明 |
| --- | --- |
| OCR 准确率 | 当前合成测试集 97.5%(39/40)。**真实凭证只会更差**，手写金额、签名、印章遮挡都没有覆盖。界面按字段给可靠度，不给"准确率 XX%"的承诺。 |
| 低对比度图借方金额 | 4/4 → 3/4（列边界误判），已知未修。 |
| OCR 耗时 | 约 2.8s/张，是换 PaddleOCR 换取准确率的既定代价。 |
| 分录金额识别 | 不解析中文数字（"三十万"）；句子里只有年份时可能被当成金额，界面会提示核对。 |
| 分录知识库 | 48 条规则覆盖用户提供的 4 张《会计分录汇总》图；原图疑似笔误（预付账款收到货物写成"销项税额"）按正确处理实现并在界面注明。 |
| 利润口径 | 按用户原图实现：投资净收益在利润总额层级加总，不计入营业利润；与现行《企业会计准则》不同，界面和导出表都写明。 |
| `styles.css` 注释乱码 | 16 行中文注释双重编码，全部落在注释内，不影响选择器与属性值。可读性问题。 |
| 产物里的 ORT wasm | `ort-wasm-simd-threaded.jsep-*.wasm`（27.6 MB raw）打进产物但 `main` 不含引用，**尚未确认是否死重量**。 |
| 懒加载失败后的恢复方式 | 失败界面只给「重新加载页面」这一个出口（整页重载）。因为实测**原地重试同一个 chunk URL 不会恢复**——浏览器会把那次失败的子资源记住。短暂的网络抖动已由自动重试 2 次覆盖。 |
| 探针依赖 preview 服务 | `probe:*` 需要先 `npm run build` 并起 preview（默认 4288）。服务没起来探针会报连接错误；`probe:all` 会自动补齐探针页，但仍需自己起服务。 |
| API 助手 | 需要自备 Key 与网络；不参与任何审计计算。 |
