# 前端可读性与移动端设计规范

本文件记录 2.2 界面改版所依据的外部规范与内部决策，避免后续回退。
所有数值都可由 `npm run validate:all` 自动校验。

## 1. 字号阶梯

问题：原实现以 14px 为基准，导致大量 10px / 11px 文字；中文在 11px 下实际不可读。

依据：

| 规范 | 要求 |
| --- | --- |
| WCAG 1.4.4 Resize Text (AA) | 文字必须能放大到 200% 而不丢失内容，因此字号必须用相对单位 |
| WCAG 1.4.12 Text Spacing (AA) | 行高至少为字号的 1.5 倍 |
| W3C Design System | 正文基准 `1rem`（16px） |
| W3C C12 | 用 `em` / `rem` / 百分比，不写死 `px` |
| Major Second 阶梯（1.125） | 密集型后台界面推荐，配合 4px 栅格取整 |
| 行业通行做法 | 正文 16px；辅助文字 13–14px；12px 仅用于全大写拉丁标签 |

阶梯定义在 `web/src/styles.css` 的 `:root`，Element Plus 的 `--el-font-size-*`
同步抬升，避免组件内文字比页面更小：

| 变量 | 值 | 像素 | 用途 |
| --- | --- | --- | --- |
| `--fs-micro` | 0.75rem | 12px | 全大写拉丁小标签（`section-kicker`、代码语言名）—— 全局下限 |
| `--fs-caption` | 0.875rem | 14px | 说明文字、表格、辅助信息 |
| `--fs-body` | 0.9375rem | 15px | 界面正文 |
| `--fs-lead` | 1rem | 16px | 对话内容等长阅读文本 |
| `--fs-title` | 1.0625rem | 17px | 卡片标题 |
| `--fs-h3` | 1.25rem | 20px | 小节标题 |
| `--fs-h2` | 1.375rem | 22px | 指标数值 |
| `--fs-h1` | 2.125rem | 34px | 页面标题 |
| `--lh-body` | 1.65 | — | 正文行高（满足 1.4.12） |
| `--lh-heading` | 1.25 | — | 标题行高 |

迁移脚本 `web/scripts/migrate-typography.mjs` 幂等地把遗留 `px` 字号映射到
`rem`，并在最后断言“没有小于 12px 的字号声明”，不满足则以非 0 退出码失败。
本次共迁移 128 条声明。

## 2. AI 对话界面

参考 2026 年主流产品（Claude.ai、ChatGPT、Perplexity、DeepSeek）的通行做法：

- **消息流限宽 768px**：约 65–80 字符一行，超过后长回答难以阅读。
- **全宽消息 + 轻背景区分**，不再使用窄气泡并排（窄气泡是旧式做法）。
- **Markdown 富渲染**：标题、列表、表格、代码块、引用、删除线、行内代码、链接。
- **无嵌套滚动**：消息流与输入区各自滚动，页面本身不滚动。
- **每条消息可复制**，输入框随内容自动增高，发送按钮 40px 便于拇指点击。

渲染器 `web/src/lib/markdown.js` 为零依赖实现，安全模型是
**先转义 HTML 实体，再做 Markdown 结构化替换**，因此模型输出无法注入标签或
事件属性；链接只放行 `http` / `https` / `mailto`。断言见
`npm run validate:markdown`（28 条，覆盖结构、安全、确定性、流式安全）。

> 注意：`v-html` 注入的内容不会带 Vue scoped 的 `data-v` 属性，
> 因此 Markdown 样式必须写在 `:deep()` 中，否则会静默失效。

## 3. 移动端

原则：**桌面与移动是同一套功能的两种密度，不是两套页面。**

- **底部标签栏**（≤820px）取代顶部横向滚动导航，5 个入口拇指可达，
  触控目标 ≥44px（实测 46–72px）。
- **“更多”面板**收纳法规速查、设置、导入数据、使用说明，避免每格过窄。
- **删除装饰性元素**：英文 eyebrow、“数据不上传”标签、英文副标题。
- **安全区适配**：`viewport-fit=cover` + `env(safe-area-inset-bottom)`。
- **表格横向滚动限制在容器内**（`overflow-x: auto`），不撑破页面。
- 聊天页在此宽度下把会话列表改为抽屉，消息流占满视口。

验证方式：`web/mobile-check.html` 以 360 / 390 / 430 / 768px 四种宽度
并排加载应用（iframe 内的媒体查询按自身宽度求值，等价于真实手机）。
实测 6 个页面在四种宽度下均无横向溢出、无小于 12px 的文字。

## 4. 徽标

`web/scripts/make-brand-assets.mjs` 从原始徽标截图生成圆形透明背景的
64 / 128 / 256 PNG，写入 `web/src/assets/brand/`（放在 `src` 而非 `public`，
以便 Vite 生成带哈希的相对路径，兼容 GitHub Pages 子目录部署）。
圆心与直径由源图像素扫描确定，脚本会同时去除截图角落的聊天界面残留。
